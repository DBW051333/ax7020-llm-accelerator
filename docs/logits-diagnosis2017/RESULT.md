# CPU / PL 固定 token 诊断结果

日期：2026-10-29，Asia/Shanghai。结论：已定位本例的初始数值差异来自 Q4_K 硬件路径的近似算术；微差经过后续模型计算放大，在相同 token 前缀下改变了候选排序。不能把此前文本分歧简单归为最后几位舍入或随机采样，也不能据此宣布模型质量可接受。

## 对照条件和真实性

- 保持原失败用例：`Write a short story about a robot.`，原始文本续写模式，无聊天模板；不更换 prompt 来避开失败。
- 同一诊断程序、同一模型、ctx256 / batch64 / ubatch64 / 双线程、temp0 / seed1234，生成24 token。模型 SHA256 为 `23c36f3a641c0062f5f60b1b98c652233a40adcc2c9f6c24df87d2e2b996248c`。
- 上游基准为 `dafae66cc242eb766797194d3c85c5e502625623`，沿用原集成补丁和既有 runtime。四实例 2017.4 overlay；本轮没有修改或重新加载硬件。
- 诊断程序 SHA256 为 `0bb8856cd740e2aadb4d43e32be1ba8740a96aa4a074d4a10d666ce76da65d71`。原体验程序 `bin/llama-cli-blite` 保持原哈希 `98dc545163e6fc8de326ca3dfc8127344287274dc61157857b1945f1cd56d91c`。
- 先记录 CPU 自由生成 token，再让 PL 每步强制输入 CPU token，记录 PL 原本会选择的 token。原始 logits 在采样器处理前保存，分析确认每步实际贪心选择等于原始 logits 的 argmax。
- CPU 诊断文本与此前 CPU 失败对照中的文本逐字节相同；CPU 两次完整 logits 逐位相同。PL 固定前缀组实际276次硬件调用，12个缓存项。强制后的输出文本相同仅是输入控制，不算模型一致性通过。

## 首次 token 分歧

前16个生成 token 的选择相同，第17个 token（记录中的 step=16）首次不同。相同前缀对应：

```text
 The robot is named "Bee" and is programmed to be a helpful assistant
```

| 候选 | Token ID | CPU logit | PL logit | PL − CPU |
| --- | --- | --- | --- | --- |
| ` for`（含前导空格） | 369 | 21.78535080 | 21.84546661 | +0.06011581 |
| `.` | 13 | 21.71784592 | 21.86869240 | +0.15084648 |
| ` to`（含前导空格） | 311 | 21.66662407 | 21.72705650 | +0.06043243 |

CPU 中 `for − .` 为 **+0.06750488**；PL 中为 **−0.02322578**，候选相对分差移动了 −0.09073067，发生排序翻转。该步151936维 logits 的最大绝对差为 **0.51696229**，relative L2 为 **0.02727780**。这已是完整网络传播后的可见差异，不是最后一位浮点误差。候选本身分差较近，但不能只凭“接近”忽略造成排序翻转的数值路径。

原始 logits 从第3个预测（step=2）就已不同，当步最大绝对差为0.44852099，只是直到第17个预测才改变贪心选择。不能把首次 token 分歧误当成首次数值分歧。

## 数值来源和因果实验

第一步 decode 的 `blk.3.ffn_down.weight`：两端4864维 F32输入和打包 Q8_K输入逐字节相同；CPU输出与同输入CPU vec_dot参考逐位相同，硬件输出与参考的最大绝对差为 **1.78813934e-7**，relative L2 为 **4.68791326e-7**。

为确认这属于当前算术设计，主机读取精确模型权重和捕获的量化激活，以整数位操作复现 RTL 的截断浮点乘法、Q18系数转换、整数累加、末端截断浮点转换，以及 runtime 的2次幂缩放。**全部896行与实际硬件输出逐位相同，0行不匹配**。这将本输入的微差对应到了已实现的近似算术语义，而不是仅猜测“CPU/FPGA舍入不同”。此验证仅覆盖首个捕获矩阵的算术，不替代时序或协议验证。

全部276个Q4调用的硬件输出，与各自同量化输入的CPU参考相比，最差 relative L2 为 **1.75728438e-6**，仍在既定1e-4局部阈值内。然而，这个阈值不能约束完整网络误差。在已捕获的Q4层中，第2步decode的 `blk.13.ffn_down.weight` 首次出现不同的Q8整数编码：543个激活编码不同，该层两端输入 relative L2 为0.00649825，输出 relative L2 为0.01657689；该次硬件相对自身同输入参考的误差仍只有2.90815428e-7。说明“同输入硬件误差小”与“两条传播轨迹接近”是不同契约。

补充明确标记的因果实验：硬件仍执行276次，但每次Q4输出都替换为该次量化输入对应的CPU vec_dot参考，随后继续网络传播。结果 **24步 × 151936维 logits 全部与CPU逐位一致**，所有采样token也相同。结合初始同输入微差和算术重放，确认本例的分歧由Q4硬件输出的近似差异触发，随后被完整网络和量化路径放大。这组参考替换只用于诊断，不能作为PL数值一致性、模型质量或加速通过。

尚未逐算子捕获第2步decode中 `blk.12.ffn_down` 到 `blk.13.ffn_down` 之间的全部运算，因此尚未确定最早发生离散编码改变的具体量化算子、元素和阈值；不能声称已定位到某一条量化指令。也未将首矩阵的微差进一步分别归因到每个截断环节的贡献。

## 判断与后续

- 对“CPU/PL逐字节相同”的目标：**当前实现不满足，需要修复或明确改变数值契约**。不能放宽局部阈值、换prompt或CPU参考替换后宣称解决。
- 对“允许近似、但质量基本保持”的目标：已经有来源明确的近似误差证据，但**是否可接受仍未验证**；需预先定义质量标准并测固定数据集上的困惑度/任务指标、稳定性和重复退化，不能用这一个prompt下结论。
- 修复研究可先定位上述层间第一个量化边界，再评估更接近CPU的乘法/转换舍入与累加方式。仅凭首矩阵位级重放，还不能保证“只改一个舍入单元”就能恢复全部生成等价。涉及硬件变更时仍须重新仿真、实现时序和板测。
